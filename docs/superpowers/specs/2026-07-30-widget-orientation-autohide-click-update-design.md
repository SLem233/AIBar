# AIBar v0.5.0 — виджет-правки, авто-скрытие, клик-вместо-наведения, авто-обновление

Дата: 2026-07-30
Форк: `chelaxian/AIBar` ← `SLem233/AIBar`
Версия: `0.4.1` → `0.5.0`

## Контекст

AIBar — PySide6-приложение для трея Windows (виджет поверх окон + дашборд +
контекстное меню). Текущая модель взаимодействия: виджет-колонка радиальных
гейджей; наведение мыши на виджет открывает отдельную полупрозрачную
HoverPanel с расширенной информацией; левый клик по иконке трея открывает
дашборд; правый клик — контекстное меню.

Четыре правки меняют UX виджета и добавляют авто-обновление.

## Цели (что строим)

1. **Авто-ориентация виджета** — вертикально у левого/правого края экрана,
   горизонтально у верхнего/нижнего.
2. **Опция «Скрывать виджет»** — авто-убирание виджета за край экрана через
   5с бездействия, выплывание при наведении на остающийся «огрызок» фона.
3. **Клик вместо наведения** — полное окно (дашборд) показывается по левому
   клику на виджет/иконку трея; наведение больше ничего не открывает.
   HoverPanel удаляется.
4. **«Проверить обновления»** — скачивание нового релиза с GitHub
   (upstream `SLem233/AIBar`) в папку Загрузки + ярлык на рабочем столе,
   всегда указывающий на актуальную версию.

## Не-цели (YAGNI)

- Никаких настроек ориентации вручную (только авто-по позиции).
- Никакого бесшумного перезаписи запущенного exe (download-only + prompt).
- Никакого CI-билда (exe собирается локально через PyInstaller по запросу).

## Фича 1 — Авто-ориентация

**Правило:** после отпускания мыши (`mouseReleaseEvent`) вычисляем ближайший
край экрана. Если виджет касается (`< THRESHOLD = 12 px`) **верхнего или
нижнего** края → горизонтальная ориентация (гейджи в ряд). Если касается
**левого или правого** → вертикальная (текущее поведение). Если не касается
ничего → сохраняется последняя ориентация (по умолчанию вертикальная).

**Реализация** (`aibar/ui/widget.py`):
- В `DesktopWidget` хранятся оба контейнера: `tiles_vbox = QVBoxLayout` и
  `tiles_hbox = QHBoxLayout`; активный определяется флагом `_horizontal`.
- Метод `_set_orientation(horizontal: bool)` снимает все tile'ы с неактивного
  layout (через `removeItem` + `removeWidget`) и перевставляет в активный,
  затем меняет `setMinimumSize` (верт. `45×60` ↔ гориз. `60×45`) и вызывает
  `updateGeometry()` + `repaint()`. Tile'ы квадратные → перетекают сами.
- В `mouseReleaseEvent` после сброса `_drag_offset` вызываем
  `_apply_edge_orientation()`, который определяет край через
  `self.screen().availableGeometry()` и `self.frameGeometry()` и вызывает
  `_set_orientation`. Между касанием краёв: верх/низ → гориз, лево/право →
  верт, ни одного → без изменений.
- На старте (`__init__`) ориентация применяется один раз к сохранённой
  геометрии (чтобы после перезапуска виджет у края сразу встал правильно).
- `QSizeGrip`, бейджи (`UpdateBadge`, `VpnBadge`) остаются; пересчёт
  `update_badge.relabel_for_width()` уже привязан к `resizeEvent`.

**Граничные случаи:**
- Многоэкранность: `self.screen()` даёт актуальный экран для текущей позиции.
- Мини-режим не конфликтует (он управляет видимостью tile'ов, не layout'ом).
- Размер виджета не прыгает резко: при смене ориентации сохраняем центр
  виджета (пересчёт `move(...)`, чтобы виджет «стоял на месте», а не
  прыгал углом).

## Фича 2 — Опция «Скрывать виджет» (авто-скрытие за край)

**Новая опция конфига:** `widget_hide_on_idle` (bool, default `False`).

**UI:**
- В контекстное меню трея добавляется чекбокс-действие **«Скрывать виджет»**,
  показываемое (или enabled) **только** когда «Виджет поверх окон» включён.
  Реализация: action создаётся всегда, но его `setVisible(...)` /
  `setEnabled(...)` синхронизируется с `widget_action.toggled`.
- То же действие добавляется в контекстное меню виджета (симметрично).

**Поведение, когда включено:**
- Таймер `_idle_hide_timer` (single-shot, 5000 мс). Запускается в
  `leaveEvent`; останавливается/перезапускается в `enterEvent`.
- На срабатывание: виджет «уплывает» за ближайший край экрана, оставляя
  видимым **sliver = 10 px** своего фона (чтобы было за что зацепиться
  курсором). Реализация: вычисляем ближайший край, считаем целевую
  координату (`move` в 2 шага для лёгкой анимации, или сразу — без
  тяжёлой анимационной подсистемы). Флаг `_hidden = True`.
- При наведении на остающийся sliver (`enterEvent` на виджете, т.к. sliver —
  это часть того же окна): флаг `_hidden = False`, виджет «выплывает»
  обратно в сохранённую (`_pre_hide_pos`) позицию, таймер стопится.
- Пока курсор на виджете — таймер не запускается (стандартный enter/leave).
- Драг виджета отменяет скрытое состояние.

**Взаимодействие с Фичей 1:** ориентация вычисляется по текущей (видимой)
позиции; при `_hidden` ориентация не пересчитывается (виджет уже за краем).

**Граничные случаи:**
- Виджет в мини-режиме: авто-скрытие работает так же (скрывается весь
  виджет целиком, а не отдельные tile'ы).
- Панель/меню открыты над виджетом: на период открытого контекстного меню
  таймер стопится (меню держит фокус; на закрытие меню — запуск таймера).
- Позиция до скрытия запоминается, чтобы выплывать ровно туда же.

## Фича 3 — Клик вместо наведения (удаление HoverPanel)

**Удаляется:** класс `HoverPanel` в `aibar/ui/widget.py` (~90 строк) и вся его
проводка (`self.panel`, `_reposition_panel`, `_hide_timer`,
`_on_panel_hover`, логика enter/leave для показа панели).

**Новое поведение:**
- Левый клик по виджету (`mousePressEvent` с `Qt.LeftButton` без начатого
  драга — отличаем по `_drag_offset` и малому смещению) → эмитит новый
  сигнал `dashboard_requested`, который в `main.py` открывает
  `DashboardWindow.show_at(...)` рядом с виджетом (как уже делает клик по
  трею). Левый клик по иконке трея → уже открывает дашборд (`on_tray_activated`
  с `Trigger`/`DoubleClick`) — без изменений.
- Правый клик по виджету → контекстное меню (уже есть через
  `contextMenuEvent`).
- Правый клик по иконке трея → контекстное меню (уже есть).
- `enterEvent`/`leaveEvent` теперь управляют **только** таймером авто-скрытия
  (Фича 2) и больше не открывают панель.

**Отличение клика от драга:** в `mousePressEvent` запоминаем стартовую
позицию; в `mouseReleaseEvent` если смещение `< ~4 px` — это клик →
эмитим `dashboard_requested`. Иначе — это был драг (не кликаем).

**Симметрия:** клик по виджету и клик по трею ведут себя одинаково
(оба → дашборд). Дашборд-попап (`Qt.Popup`) уже закрывается по клику вне его.

## Фича 4 — «Проверить обновления» (скачивание + ярлык)

**Новый модуль:** `aibar/updater.py` — слой действия (скачать + применить).
Существующий `aibar/update.py` (сравнение версии, бейдж) **остаётся** как есть.

**Источники** (без изменений — upstream по выбору пользователя):
- `LATEST_RELEASE_API = https://api.github.com/repos/SLem233/AIBar/releases/latest`
- `RELEASES_URL = https://github.com/SLem233/AIBar/releases/latest`

**Класс `Updater` (QObject, фоновый поток):**
- `check_and_download()`:
  1. GET `LATEST_RELEASE_API` → `tag_name`, список `assets` → ищем asset
     с именем `AIBar.exe`, берём `browser_download_url` и `size`.
  2. Парсим версию (`_parse_version` из `update.py`, переиспользуем) → если
     `latest <= current` → сигнал `up_to_date(str current)` (молчаливо или
     диалог «у вас последняя версия»).
  3. Если новее → скачиваем `browser_download_url` в
     `Загрузки/AIBar-v<latest>.exe` потоково (`requests.get(stream=True)`,
     чанками), с прогрессом → сигнал `progress(int percent)`.
  4. После успеха: удаляем старые `Загрузки/AIBar-v*.exe` (кроме текущего),
     (пере)создаём ярлык на Рабочем столе `AIBar.lnk` → на новый файл.
  5. Сигнал `downloaded(str version, str path)`.
- Ошибки сети/asset-не-найден → сигнал `failed(str message)` (молчаливо, как
  `UpdateChecker`, плюс тихое всплывающее уведомление трея при ручном
  запуске).

**Папка Загрузок / Рабочий стол:** через `os.environ["USERPROFILE"]/Downloads`
и `os.environ["USERPROFILE"]/Desktop` (с фолбэком на `Path.home()` и
`QStandardPaths` при отсутствии). Ярлык `.lnk` создаётся через
`powershell`-вызов (`WScript.Shell` COM) или `pywin32`, если доступен; иначе —
через subprocess `powershell -Command "$ws=New-Object -ComObject
WScript.Shell; $s=$ws.CreateShortcut('...'); $s.TargetPath='...';
$s.Save()"`. Без новой жёсткой зависимости — powershell есть на любой Win10+.

**UI:**
- Действие **«Проверить обновления…»** в контекстном меню трея и виджета.
- При нажатии: если есть бейдж обновления (уже известно) — сразу качаем;
  иначе — вызываем `check_and_download()`.
- Прогресс: переиспользуем плашку `UpdateBadge` (показывает «↓ X%») или
  простой `QProgressDialog` (non-modal, можно отменить). Выбор: `QProgressDialog`
  — стандартный, с кнопкой «Отмена» → прерывает скачивание.
- По завершении: модальный диалог
  «Скачана версия X.Y.Z. Перезапустить AIBar для применения?»
  **[Перезапустить] [Позже]**. «Перезапустить» → запустить новый exe
  (через созданный ярлык или прямой путь) отдельным процессом и
  `app.quit()`. «Позже» → закрыть диалог (файл уже в Загрузках, ярлык
  обновлён — пользователь запустит сам).

**Безопасность/отказ:** скачивание идёт только по явному действию
пользователя; HTTPS; размер проверяется по `size` из asset'а (опционально).
Файл не исполняется автоматически кроме как по выбору «Перезапустить».

## Риски / компромиссы

- **Ярлык без новой зависимости:** powershell COM — надёжно на Win10+,
  но не кроссплатформенно (приложение и так Windows-only).
- **Download-only без авто-перезаписи:** пользователь должен нажать
  «Перезапустить» — осознанный выбор (менее «магично», но надёжно).
- **Upstream как источник обновлений:** релиз на форке не найдётся кнопкой —
  задокументировано выше.
- **Анимация уплывания/выплывания:** минималистичная (2-шаговый move),
  без QTimer-animation-подсистемы, чтобы не раздувать код.
